# Q版多角色动作执行与持续表演

本文件保存多人同框时的动作过程、状态交接与非主行动角色表演方法。它解决的是“角色怎样连续活在同一个场景里”，不规定某个角色必须使用某种动作。

## 读取时机

出现以下任一情况时读取：

- 两名以上 Q 版角色依次执行动作；
- 某个角色完成动作后仍留在画面中；
- 用户只给出“前空翻、跑来抱腿、递东西”等核心动作，需要补齐物理过程；
- 动作虽能完成，但其他角色在等待期间像被暂停；
- 需要让前一段的结果自然成为后一段的起点。

## 1. 主要动作写成可执行状态链

不要让一个动词独自承担动作控制。关键动作按需要补齐：

```text
起始位置与身体状态
→ 触发信号／发力或蓄力
→ 动作进行中的可见过程
→ 减速、接触或缓冲
→ 动作完成后的稳定状态
```

只写当前动作真正需要的阶段，不为填满结构增加无意义步骤。

例如“菲比前空翻”可以展开为：

```text
站在玄关中间稍后方
→ 向前跑两小步、屈膝摆手
→ 向前腾空并完成一次旋转
→ 弯膝落地、小手短暂扶地缓冲
→ 在 POV 双脚前方站稳并抬头
```

前空翻只是本案例动作，不是菲比的固定 Canon。

## 2. 用稳定结果完成状态交接

一个动作结束时留下的状态，应成为后续段落的已知起点。至少检查：

- 角色完成动作后位于哪里、朝向哪里；
- 双脚、重心与身体姿态是否已经稳定；
- 是否仍持有原道具；
- 是否已经与 POV、另一角色或物体建立接触；
- 下一段开始时哪些状态必须继续保持。

不要让角色在时间段之间瞬移、自动复位、换手、丢失道具或无故解除接触。

## 3. 每段一个主要动作，其他角色维持持续表演

每个时间段指定一个主要行动者。其他已入画角色先保持既有站位、道具与接触状态；在不干扰主要动作、不过度增加模型执行负担时，可以补充一个低强度反应，例如：

- 转头或移动视线追随主要行动者；
- 眨眼、改变嘴角或露出符合当下的表情；
- 调整重心、站姿或手的位置；
- 轻微点头、招手、前倾或让出一点空间；
- 继续维持抱住、托举、依偎或等待等已有状态。

这不是“所有角色必须一直动”。静止可以是合理表演：安静等待、情绪停顿、维持接触，或为了避免同一段动作过载。目标只是**尽量避免角色在没有原因时长时间像被暂停**。

若画面已经包含复杂运动、多人接触或关键道具交接，优先保证主要动作，省略次要反应。

## 4. 用户只给核心动作时的自动补全边界

当用户只指定核心动作时，可以自动补：

- 动作成立所需的起势、发力、惯性、缓冲与站稳；
- 动作完成后的合理位置、朝向和身体状态；
- 不抢戏的注视、表情、重心变化或轻微回应；
- 为下一名角色让出动作路径所需的最小位移。

不得自动补：

- 第二次主要动作；
- 新道具、新能力或新角色；
- 改变事件顺序的剧情；
- 抢走下一名角色职责的互动；
- 与角色性格或用户指定结尾冲突的表演。

如果自动补充会改变核心事件、结尾或角色关系，先询问用户。

## 5. 编排卡

写多人动作段落时，可在内部使用：

```text
【当前主要动作】
执行角色：
起始状态：
动作过程：
接触／缓冲：
稳定结果：

【其他已入画角色】
必须保持：
可选低强度反应：
本段不得抢走的动作：

【交接到下一段】
各角色位置与朝向：
仍维持的接触：
道具持有者与位置：
下一位主要行动者：
```

这张编排卡用于写作检查，不要求逐项复制进最终 Prompt。

## 6. 当前案例中的应用

已记录案例：[`validated-case-welcome-home-front-flip-pillow-leg-hug.md`](validated-case-welcome-home-front-flip-pillow-leg-hug.md)。

该成片与用户反馈支持：

- 菲比的前空翻通过起跳、旋转、落地缓冲、站稳形成了清楚过程；
- 菲比站稳后的落点成为 Sera 与糯糯后续动作发生时的持续空间状态；
- Sera 先抱腿，糯糯再迟疑、放下枕头、加入抱腿，主要动作按顺序交接；
- 道具、人物位置与 POV 接触关系可以在同一镜头中连续累积。

“在其他角色行动期间，为已完成动作的角色增加低强度反应”是从该案例复盘得到的后续编排方法。它应作为有余量时的默认考虑，而不是已经证明所有模型与场景都必须采用的硬规则。
