# 已有剧情转视频提示词

用于用户交代剧情后要求生成视频 Prompt，或说“先按照模板生成”。这是 Chibi 原流程的交付分支，不要求先运行其他视频 Skill、读取 video-exp 或启动分工 Agent。

## 继承剧情，再补执行

1. 直接继承本次角色、目标、刺激、事件顺序、关键选择与结尾。已有剧情不要求重新批准，也不因为使用模板而换故事、增加角色、加入温馨和解或固定爆炸收尾。
2. 只确认会改变身份、主要事件、结尾、声音权限、参考绑定或接触条件的缺口；人物关系解释到支持本集即可。普通机位、构图、节奏和生活空间由导演提出方案。
3. 从每段实际变化确定观众需要看清的证据，再决定切镜或保留实时连续动作。剧情段、场景、实际镜头与一次生成分别安排；蒙太奇包含切镜时拆镜号，镜内阶段不冒充切镜。
4. 把“生气、反击、处罚、收拾好”等意图翻译成可见过程：刺激与视线对象、起始位置／支撑、行动路径、接触与反馈、结果及下一段继承状态。写清谁拿道具、谁被击中、谁选择下一行动。
5. 以 [统一模板](../assets/clean-template.md)交付：参考资产职责、全局要求、逐镜景别／机位、画面、台词／拟声／声音、出片要点和失败保险。**制作备注：先按照模板生成。** 这条备注给提示词作者执行，不写入视频模型的画面正文。

已有完整剧情且用户要全片 Prompt 时，交齐所有已定生成片段，不只给一段示范。用户只要某段就完成某段，不重跑全片。已有 BASE 的继承任务保留原结构与授权范围。

## 时间、参考和声音

- 策划中的连续时间区间采用同一口径，相邻边界衔接，段长与区间跨度一致，合计满足目标时长。整片位置与每次生成从 0 开始的局部时间分开；精确时间戳是否进入模型正文仍按主入口分层规则决定。
- 只绑定实际提供并查看的素材。只有图一／图二时使用当前图号；平台有真实 key 才写对应 key，不生成假绑定。
- 模板空栏用于发现缺口，不代表必须准备每种资产。普通道具和环境不因空栏而额外生图；关键身份参考确实缺失时，明确交付为待绑定草案，不声称已可提交。
- 台词栏只写角色实际发出的内容。作者层“我想证明自己”等思想，通过表演呈现，不放进引号或括号冒充音频。分别处理 Q 版固定拟声、新 Q 版和本体权限。

导演理由、制作假设、素材缺口和验证状态放在复制区外。每镜出片要点只保护最关键的 1–3 项，不重复全文。交付前集中检查剧情是否被改写、数量／身份／声音是否正确、关键动作与镜头是否有过程、跨段是否接住同一道具及情绪结果。
