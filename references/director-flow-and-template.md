# Q版导演流程与模板交接

用于把已确认的 Q版事件或完整故事变成镜头与提示词。日常片段保持轻量；需要解释拍法、跨片段叙事或找模板缺口时再展开。本文件维护 Q版所需的本地协作方法，不要求另一个视频导演入口可用。

## 入口与故事边界

| 当前输入 | 处理与交付 |
|---|---|
| 信息完整的日常片段 | 核心事件 → 第一帧与必要镜头设计 → 资产检查 → Prompt；新创作无时长时仍默认 15 秒 |
| 零散的完整短剧 idea | 整理已知目标、行动原因、未定选择与结尾，进入故事探索；不直接填满正式视频 Prompt |
| 已批准的完整剧情 | 提取事件链，直接设计开头、分场、镜头和生成单元，不重新要求批准同一故事 |
| 已有成功 BASE 或部分成片 | 从当前阶段继续，按 Minimal-Delta Mode 保留已接受部分 |

1–5 分钟是常见短剧规模，不是硬阈值。用户只处理长片中的一段时，直接进入该片段并继承上下文。不得因使用此流程而改变用户总时长或 BASE 时长。

把因果提取为“为什么行动 → 当前要完成什么 → 已定阻碍／选择 → 改变什么”。只记录现有事实，不为每个日常动作添加冲突，也不把性格倾向直接编成新剧情。

需要正式探索或改写故事时，通过已连接 GitHub 的文件工具读取 `weoiquan-art/JIN-Story-Development` 的 `SKILL.md` 及其当前所需参考；工具未展示先发现读取能力。公开网页或 raw 访问失败不证明授权连接器不可读。交接实际 Q版角色、固定拟声权限、已有事件、禁区、目标时长与未决项，明确不是成女 Sera；不自动调用成女世界观。

故事候选与新增动机、选择、重要信息和结局标明草案，用户选定后再执行。只缺构图、机位或节奏的故事无需回到故事开发。外部故事资料确实不可读时如实说明、完成已能做的 brief；已有获批剧情仍可继续本地导演流程。

## 从剧情到整片安排

各职责可由同一个 GPT 完成，不要求启动多个 Agent：

| 职责 | 接收与交出 |
|---|---|
| 需求理解 | 区分已确认事实、执行选择和重要未决项；合并本轮问题 |
| 故事开发 | 形成并确认动机、选择、后果、事件顺序与结尾 |
| 整片导演 | 决定开头所见、信息释放、分场作用、总时长及资产准备 |
| 场戏与镜头 | 安排节拍、具体镜头数、切镜／连续观察理由、构图与注意力 |
| 表演与动作 | 把已有意图转成当前机位能见的身体过程、协作与声音 |
| 资产与连续性 | 核对真实引用、跨段角色／道具／空间／情绪状态，汇总最终 Prompt |

完整故事先交付简洁的整片方案：第一眼看什么、为何从这里开始、观众依次知道什么、每场承担什么、结尾如何接收前面的结果。遵守已定事件顺序；会改变悬念身份、核心因果或结局的信息重排先作为故事提案。

| 场号 | 地点与入口 | 获批事件／观众新获得的信息 | 出口状态 | 策划时长 |
|---|---|---|---|---|
| S01 |  |  |  |  |

填写本片实际方案并核对合计，不用“按需”代替决定，也不用重复空镜填时长。内容容量不足时说明缺口并提出选择，不擅自缩短或增加剧情。

“平和—起伏—平和”是可选节奏，结尾的平和仍可留下新的安心、疲劳或关系状态。治愈、喜剧、追逐、协作各有密度；不把所有内容写成打斗，也不要求每片反转。原始方法论保留的阶段数量建议作为容量参考，不变成切镜配额。

## 镜头、构图与表演

文字分镜用来分配观众注意力、事件时序与执行条件，不等于必须逐镜制作图片。每镜决定一个主要叙事任务；可有多个内部阶段与协作双方。先说清本片推荐的镜头数、剪切次数和关键镜内景别变化，再简述关键选择：

- 保留这一镜要让人看清什么；删去会失去什么。
- 在此切镜是因为新信息、反应、空间／时间或可控生成的需要；连续拍摄是为了保留实时互动、路线或因果。
- 一镜到底仍安排人物走位与注意力交接；阶段变化不自动切镜。
- 景别要容纳当前证据：脸部反应、双方接触、脚步承重或整体空间；近景看不到的脚部细节留给合适镜头。
- 构图写主体在哪、目标在哪、接触能否同框、什么遮挡什么、何时揭示。前中后景与留白有作用才写，不为填格子堆装饰。
- 画面大小或角度变化明确由摄影机、角色位移还是 POV 身体行为造成；继承已定的手机 POV 载体，普通运镜不自动改成第三人称。

模型正文中的“画面”沿同一时间线融合人物、道具、镜头和环境：起始条件 → 发力／可见反应 → 过程与接触 → 对方响应／环境证据 → 可继承结果。只写当前动作需要的细节；安静的视线和呼吸无需扩成全身发力链。

两人递接、共同推物、扶稳或已批准的对抗，允许双方动作同时服务一个主要目标。用 [多人动作参考](multi-character-action-continuity.md) 保持先后、承重、惯性与结果；旁人低强度表演按余量安排。受力与环境反馈服从 Q版小体型和本片世界条件，不自动加入能量光效或破坏。

固定拟声词由 [角色资料](four-character-canon.md) 决定，长篇也不自动获得完整人类对白权限。拟声、动作声、静默和已批准的声音桥在镜头设计时安排；不靠声音另造画外故事。发声先后、语气、距离和必要口型写进对应镜头。

## 生成单元与连续性

分清三种单位：场号 S01；实际连续观察的镜号 S01-01；一次生成的单元 G01。一个单元可有多镜，同一镜也可能分单元接续；不把每个动作阶段独立编号为切镜。

| 单元 | 对应镜头 | 整片位置／预计可用长度 | 本次生成时长 | 所需实际资产 | 进入 → 交出状态 |
|---|---|---|---|---|---|
| G01 |  |  |  |  |  |

总片长、预计可用片长与生成长度分开核算。整片第几分钟写在制作表；本次 Prompt 使用从 0 开始的局部区间或明确相对顺序。生成时长与素材容量按用户给定制作条件或当前入口核对，未知写假设，不把一部长剧当一次生成。

日常环境、普通道具与常规动作仍沿用轻量资产原则。先查全片可复用资料，再为每单元选实际使用的子集；不因为模板有关键帧一栏就要求生图。独特结构、复杂空间或实际失败确需资产时，说明它锁什么、缺失影响哪一镜。

跨段继承实际角色与外观、摄影机侧别、位置和路径、同一道具及持有者、持续接触、衣物／环境变化、情绪和呼吸。计划出口不是实际尾帧；生成后以验收结果为准，不虚构已无缝接上。若错在关键事件，先修该段，不为接续修改故事。

## 最终模板与缺口

采用 [统一模板](../assets/clean-template.md)，每个生成单元独立可复制。复制区外放导演理由、整片时间位置、当前资产状态与待办；区内放实际规格、参考职责、全局要求和逐镜“画面／拟声·声音／出片要点”。

| 字段发现的缺口 | 怎样处理 |
|---|---|
| 已确认的角色、事件或声音 | 从当前材料继承，不重复问 |
| 景别、构图、机位、观察距离、节奏 | GPT 提出具体执行方案；不改变故事时继续 |
| 动机、关键选择、结局或改变到达／接触／揭示的空间条件 | 由需求理解集中提问，每轮所有环节共用最多 3 问 |
| 参考文件缺失或未验收 | 区分能文字生成的普通内容与身份／关键结构；可交规划草案，不能假称实际绑定 |

角色图、素材标签或上传次序未知时，不编造 `图1` 或 `{{key}}` 已经可用。用户要完整提示词时覆盖全部已定单元；缺资产的单元明确标“规划草案”，不把局部缺口变成整片规划停止。

## 交付检查与证据

核对总时长、局部时间、镜头与生成映射；核对第一帧、动作因果、可见证据、道具唯一性、Q版发声及跨段状态。原稿继承任务优先 Minimal-Delta，不因模板升级重排成功措辞。

本次同步规定的是写作与交付方法，不宣称新模板已经通过视频生成验证。保留 Claude 原始方法论及所有样本的原文和证据状态；其反转、阶段数与时长建议按当前事件选用。后续真实成片仍按原有复盘流程记录正确处、偏差与最小修改。
