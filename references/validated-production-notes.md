# Q版短视频：已验证生产备注

本文件用于记录用户在真实日常生成流程中确认的增量经验。不得覆盖 `claude-original-methodology.md` 原始经验；新规则作为生产层补充持续累积。

## 1. 区分“作者层标记”与“视频模型输出层”

### 结论

角色拟声词中的 `~`、`！` 等标点，主要用于帮助**负责写视频提示词的 AI**理解声音的情绪、长度和强度。

例如：

- `菲比啾比~~` → 理解为较长、柔软或撒娇的拉长音；
- `菲比！` → 理解为短促、兴奋、强调；
- `菲比啾比~~~！` → 理解为明显拉长且高兴、兴奋的呼喊；
- `糯糯~`、`Sela~` 同理。

这些属于**作者层语义标记**，不是要求最终视频生成提示词额外解释的技术语法。

### 最终视频提示词怎么写

最终交给 Seedance 等视频模型时：

- 可以直接保留角色实际要发出的拟声词文本；
- 可以直接写语气，例如“开心地拉长声音”“短促兴奋地喊”“轻轻软糯地发声”；
- 不需要再写“可以通过 `~`、`！` 改变情绪”“标点用于控制拉长音”等元说明；
- 不把面向提示词作者的规则说明混入面向视频模型的成品提示词。

### 两层示例

作者层理解：

```text
菲比：菲比啾比~~
= 温柔、满足、稍微拉长
```

最终视频提示词：

```text
音频：菲比贴近镜头，满足地拉长声音说“菲比啾比~~”。
```

而不是：

```text
可以通过“~”改变拉长音和情绪强弱。
```

### 原则

**内部规则帮助 AI 写得更准；最终 Prompt 只保留视频模型执行画面和声音真正需要的信息。**

## 2. 已验证成功 Prompt 不能被直接覆盖

### 结论

被用户明确确认成功、满意、爆款或作为原版基准的 Prompt，属于生产证据和可复用母版。后续发现空间、动作或表述问题时，不得直接覆盖母版原文。

### 版本处理规则

- **母版冻结**：成功 Prompt 保留原文件、原结构和原措辞，作为 BASE 证据；
- **修正另存 variant**：后续空间修正、动作替换、角色增减或模型适配另存新文件，并在文件名或说明中标清变体职责；
- **变体不反向改写母版**：variant 可以引用母版，但不能因为“更新”“更合理”或“更安全”而取代历史成功证据；
- **继承优先最小改动**：用户要求基于成功版修改时，先找 BASE，再区分 PRESERVE / CHANGE / DEPENDENCY CHANGE，只修改点名内容和必要联动；
- **不静默换 BASE**：若母版与修正版同时存在，必须根据用户指名选择；无法唯一判断且选择会改变成片时，先确认。

### 《欢迎回家》当前版本职责

- `welcome-home-15s-template.md`：原始成功版冻结母版，不再覆盖；
- `welcome-home-15s-template-door-outside-variant.md`：门外 POV 空间修正版；
- 后续新的动作或角色版本继续另存 variant，不直接写回冻结母版。

### 角色名单继承防错

模板中的角色名单不是不可修改的固定结构。用户当前请求的角色名单优先：

- 本次没有点名的角色不得从母版、variant、上一版 Prompt 或参考图中自动继承进主线；
- 只有用户明确要求后景 OB / IP 活水印时，未点名角色才可以作为背景存在；
- 删除角色时，同步删除该角色的动作、声音、参考图职责和专属失败保险；
- 不得为了保持旧模板人数而擅自补回角色。



## 3. “路过”被写成“远距离靠近”：抽象意图被具体空间程序覆盖

### 样本来源

用户原本要的是：

- 类似美国乡村街边的人行道；
- 沿 POV 前进方向，左侧是房屋，右侧是绿树；
- 第一可见帧里，POV 已经从三小只旁边经过，三人已经围在一起；
- 菲比已拿着饼干，Sera 已拿着冰淇淋，糯糯已拿着相机；
- 菲比与 Sera 立即向 POV 分享食物，糯糯同时给 POV 拍照；
- “路过”是故事已经开始时的空间关系，不需要先用半段视频寻找或靠近她们。

实际 Prompt 却加入了：

- “远处可以看见三个小小身影”；
- “POV 继续向前”；
- “随着距离接近”；
- “进入清楚中景”。

实际成片据此把三小只放在道路／地平线远处，用约前 4–5 秒让摄影机向她们推进；场景也被补成开阔的临水广场式步道，三人最后正面排开。用户想要的“已经在旁边路过并立刻互动”，变成了“远处发现后走向三人”，互动时间被挤到后半段。

### 用户原话（2026-09-21）

> 视频模型更服从具体、可视化的空间与动作语句，而不是上层的抽象意图。

### 可复用结论

这次并不是视频模型完全不理解“路过”，而是 Prompt 中更具体的空间和动作命令重新定义了故事：

```text
抽象标签：路过
具体执行：远处出现 → POV 继续向前 → 距离接近 → 进入中景
模型更可能执行的实际故事：靠近三小只
```

因此：

1. **故事开始必须等于第一可见帧。** 用户要“已经在旁边”，第一帧就处于可互动距离；
2. **距离变化不是免费铺垫。** 远处发现、走近、缩放、寻找、转身都会成为真实镜头动作并消耗秒数；
3. **环境方向必须落成画面轴线。** “乡村街边”不足以锁构图；若左右地理决定观感，就写清摄影机前进方向、左侧房屋、右侧绿树；
4. **角色初始行为要在第一帧成立。** 已经围在一起、手中已有饼干／冰淇淋／相机，不要先让模型花时间集合、取物或排队；
5. **最后检查具体句是否背叛抽象词。** 暂时删掉“路过”“偶遇”等标签，只读第一帧、空间和动作句；如果读出的仍是“走向她们”，就说明 Prompt 尚未表达用户真正想要的路过。

### 粗略描述时 AI 应怎样补问

用户只给抽象场景时，不要求用户先懂分镜术语。若以下缺口会改变成片，合并成一个短问题确认：

- 第一帧已经在互动距离，还是需要从远处接近；
- POV 沿哪条方向运动，是经过、迎面靠近、停下，还是回头；
- 重要环境分别位于画面哪侧；
- 角色已经在做什么、手中已有何物；
- 是否允许建立过程占用前几秒。

若用户明确要求直接写且不等待确认，采用最少假设：从核心事件成立的距离开场，不自行添加远距离发现、长距离走近或无动机缩放。

### 与通用视频提示词 Skill 的关系

通用视频提示词 Skill 已经有同一理论骨架：把抽象叙事翻译成“当前机位能看见的事实”，先锁第一帧占位、空间 blocking、摄影机所在一侧和动作因果；昨天基于 Sera 生产复盘新增的“先验收实际资产”“沿制作链定位偏差最早出现阶段”也支持同一判断。

本案例补足的是 Q版 POV 短视频中特别容易漏掉的一层：**抽象的空间动词若与具体时间线冲突，模型会按具体时间线重写故事；第一帧距离和摄影机路径必须在写动作前确认。** 该方法现已直接写入本 Skill，不依赖外部视频 Skill 才能执行。

## 4. “真实手机实拍风格”与“第一人称手持手机 POV”不是同义词

### 样本来源

在猫眼轮流扮可爱的提示词中，助手把《欢迎回家》成功母版的：

> 真实手机实拍风格，第一人称 POV 手持手机拍摄

改写成了：

> 真实第一人称双眼 POV

用户立即指出画风不对，并追问《欢迎回家》原本怎样描述。随后助手虽然找回母版原句，却又在另一版里再次使用错误视角，因此用户要求把这次错误永久记住。

### 用户原话（2026-09-22）

> 画风似乎不对，欢迎回家是怎么形容的，是实际第一人称？

> 怎么又写错了，这个要记得。

### 结论

“真实手机实拍风格”负责锁定**成像媒介与画面质感**；“第一人称 POV 手持手机拍摄”负责锁定**摄影机身份和运动方式**。两者必须分别保留：

- “真实第一人称”只表达观看关系，不能替代手机实拍质感；
- “人的双眼 POV”会把摄影机载体从手机改成人眼，不是优化或同义改写；
- 继承《欢迎回家》时，这两句属于固定层和 Minimal-Delta Mode 的 PRESERVE 内容；
- 特殊观察动作（猫眼、门缝、窗户）只改变手机镜头的位置、遮挡或光学效果，不自动改变 POV 载体；
- 只有用户明确要求裸眼视角或取消手机拍摄时，才能改写。

### 交付前检查

对所有沿用当前 Q版实拍系列的 Prompt，单独核对：

1. 是否仍明确写着“真实手机实拍风格”；
2. 是否仍明确写着“第一人称 POV 手持手机拍摄”；
3. 是否误写成“人的双眼 POV”“裸眼 POV”或只剩抽象的“第一人称”；
4. 是否因为某个观察动作而无授权改变了摄影机载体。

固定层正确后，再编排当前剧情动作；不得用动作合理性为理由静默改写画风。

## 5. 海滩跌倒：松软沙与角色接触的可见反馈（单次成片案例）

### 样本与原话（2026-09-23）

用户上传约 15.07 秒、9:16 的沙滩成片；上传文件名为“15秒厨房Q版角色等面视频 (4).mp4”，但视频画面确实是粉色海水、遮阳棚、沙滩椅和菲比／咕嘎奔跑跌倒的海滩场景。糯糯与 Sera 坐在旁边观看。

> 成果还不错 我注意到 你写的松软沙 部分有在视频体现 角色 和沙子的动态有体现到 适合存储到案例里

本聊天此前写过 17 秒、无分段时间轴的候选 Prompt，其中与地面接触直接相关的原句节选：

> 菲比的一只脚踩进松软沙地，上半身先向前倾。她挥一下小手找平衡，小脚却追不上身体；双手先碰到沙面，随后整个人轻轻向前扑倒，滑出一小段才停住。

另一段写咕嘎追在后方、迈步受阻、重心继续向前并扑进菲比后方稍偏一侧的沙里。尚未核对用户最终投喂的完整文本、参考资产和生成设置；候选稿写 17 秒，实际成片约 15 秒，不能把两者当作逐字一致的输入输出。

### 成片中可直接观察的事

- 开头 POV 脚边已有沙面纹理；菲比和咕嘎向海边跑时，脚下出现一条明显的踩踏轨迹，沙面随行进呈现凹痕及被推起的沙块，后续镜头仍看得到。
- 菲比先在前方扑倒，咕嘎随后停顿并倒在稍后方；两人的身体贴近沙面，直至结尾仍趴着。地面、行进轨迹和结束位置在同一视角里连续可见。
- 脚印／沙块相对掌心大小角色偏大；咕嘎是否准确踩到菲比伸出的小脚，在成片中无法清楚确认。因此本例验证的是**松软地面有可见的踩踏与接触反馈**，尚未验证精确的尺寸比例或绊倒接触点。

### 下次写提示词可借鉴的候选写法

把材质放进动作因果：**脚踩进松软沙 → 沙在受力处下陷并留下小脚印 → 失衡时手掌触沙、身体落下 → 停住后脚印与接触痕迹仍在**。提示词同时给出接触部位、沙的局部变化与动作结束后的状态，比只说“在沙滩上跌倒”更具体。脚印尺寸需要随角色体型写清楚。本条来自一次成片与用户反馈，作为可复用案例保留；待更多样本验证后再考虑升级为通用硬规则。



## 6. 《欢迎回家》照顾链：15 秒不必强制反转

### 证据来源

- 冻结母版：`welcome-home-15s-template.md`；
- 用户说明该 Prompt 生成的《欢迎回家》成片获得三万多点赞；
- 用户补回的历史聊天记录将其优势归纳为：开门即被等待、三角色各有功劳、连续的小温暖动作、POV 回应、必要玄关锚点与群像定格；用户明确认同这是一条强爆款结构；
- 用户选择的 15 秒加强方向是把原有效动作链拉完整，不增加无关反转。

这些证据支持“照顾型连续奖励”作为高价值内容结构；不能据此断言某个单独动作或某一句 Prompt 是点赞表现的唯一原因。

### 对原始方法论的增量修正

`claude-original-methodology.md` 第 7 节把“约 15 秒以上建议至少加入一次预期违背”作为早期经验。保留该原文作为历史基线，但生产层不把它执行为硬规则。

《欢迎回家》验证了另一条 15 秒路线：

```text
已经在等待
→ 直接照顾
→ 活跃角色加码
→ POV 给予回应
→ 安静角色处理生活细节
→ 群像稳定收尾
```

整条视频保持同一个温暖情绪方向，却通过多个不同的小奖励节点持续推进，因此不依赖剧情反转。

### 可复用结论

1. **开场立即兑现关系。** 第一可见事件就让观众读到“她们在等你回家”。
2. **差异来自行为选择。** 每名角色为同一迎接事件贡献不同功能，不做同步复制动作。
3. **POV 必须真实回应。** 接物、摸头、蹲下或递出物件让观众进入互动，而不是只观看角色表演。
4. **照顾动作依次发生。** 一个完成或稳定后再把注意力交给下一个，形成连续奖励。
5. **场景只保留动作锚点。** 入口、拖鞋落点、钥匙盘等足够支持事件，不为生活感堆家具。
6. **最后一帧承担记忆点。** 角色动作减速，形成清楚、温暖、可停留的欢迎构图。
7. **扩展时长先补过程。** 补足发力、移动、接触、减速、结果与 POV 反馈，再判断是否需要新节点。

### 使用边界

- 本案例中的递拖鞋、滑铲、争摸与收钥匙不是角色硬绑定 Canon；
- 新题材按当前角色名单重新分配“直接照顾／活跃加码／安静收束”等功能；
- 用户要求沿原版修改时，仍以冻结母版为 BASE 执行 Minimal-Delta Mode；
- 详细结构读取 `welcome-home-care-pattern.md`，不在最终 Prompt 中复述本段理论。
