# Q版短视频：已验证生产备注

本文件用于记录用户在真实日常生成流程中确认的增量经验。不得覆盖 `claude-original-methodology.md` 原始经验；新规则作为生产层补充持续累积。

## 1. 区分“作者层标记”与“视频模型输出层”

### 结论

角色拟声词中的 `~`、`！` 等标点，主要用于帮助**负责写视频提示词的 AI**理解声音的情绪、长度和强度。

例如：

- `菲比啾比~~` → 理解为较长、柔软或撒娇的拉长音；
- `菲比！` → 理解为短促、兴奋、强调；
- `菲比啾比~~~！` → 理解为明显拉长且高兴、兴奋的呼喊；
- `糯糯~`、`Sela~` 同理。

这些属于**作者层语义标记**，不是要求最终视频生成提示词额外解释的技术语法。

### 最终视频提示词怎么写

最终交给 Seedance 等视频模型时：

- 可以直接保留角色实际要发出的拟声词文本；
- 可以直接写语气，例如“开心地拉长声音”“短促兴奋地喊”“轻轻软糯地发声”；
- 不需要再写“可以通过 `~`、`！` 改变情绪”“标点用于控制拉长音”等元说明；
- 不把面向提示词作者的规则说明混入面向视频模型的成品提示词。

### 两层示例

作者层理解：

```text
菲比：菲比啾比~~
= 温柔、满足、稍微拉长
```

最终视频提示词：

```text
音频：菲比贴近镜头，满足地拉长声音说“菲比啾比~~”。
```

而不是：

```text
可以通过“~”改变拉长音和情绪强弱。
```

### 原则

**内部规则帮助 AI 写得更准；最终 Prompt 只保留视频模型执行画面和声音真正需要的信息。**

## 2. 已验证成功 Prompt 不能被直接覆盖

### 结论

被用户明确确认成功、满意、爆款或作为原版基准的 Prompt，属于生产证据和可复用母版。后续发现空间、动作或表述问题时，不得直接覆盖母版原文。

### 版本处理规则

- **母版冻结**：成功 Prompt 保留原文件、原结构和原措辞，作为 BASE 证据；
- **修正另存 variant**：后续空间修正、动作替换、角色增减或模型适配另存新文件，并在文件名或说明中标清变体职责；
- **变体不反向改写母版**：variant 可以引用母版，但不能因为“更新”“更合理”或“更安全”而取代历史成功证据；
- **继承优先最小改动**：用户要求基于成功版修改时，先找 BASE，再区分 PRESERVE / CHANGE / DEPENDENCY CHANGE，只修改点名内容和必要联动；
- **不静默换 BASE**：若母版与修正版同时存在，必须根据用户指名选择；无法唯一判断且选择会改变成片时，先确认。

### 《欢迎回家》当前版本职责

- `welcome-home-15s-template.md`：原始成功版冻结母版，不再覆盖；
- `welcome-home-15s-template-door-outside-variant.md`：门外 POV 空间修正版；
- 后续新的动作或角色版本继续另存 variant，不直接写回冻结母版。

### 角色名单继承防错

模板中的角色名单不是不可修改的固定结构。用户当前请求的角色名单优先：

- 本次没有点名的角色不得从母版、variant、上一版 Prompt 或参考图中自动继承进主线；
- 只有用户明确要求后景 OB / IP 活水印时，未点名角色才可以作为背景存在；
- 删除角色时，同步删除该角色的动作、声音、参考图职责和专属失败保险；
- 不得为了保持旧模板人数而擅自补回角色。
